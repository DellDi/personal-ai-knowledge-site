## 选型原则

<Callout variant="info" title="原则">
  每一层选型都遵循“读侧和写侧分开，两边用最合适的工具”。不追求单框架大而全，而是让每个工具做它最擅长的事。
</Callout>

## 数据库：为什么直接 PostgreSQL

<Steps>
  <li>本地用 docker-compose 起 PostgreSQL 16，开发生产同一镜像</li>
  <li>避免 SQLite → PostgreSQL 的迁移折返</li>
  <li>后续 pgvector 扩展直接复用同一实例做 AI 向量检索</li>
</Steps>

## 对象存储：为什么阿里云 OSS

<StatGrid
  items={[
    { value: 'S3 兼容', label: 'Payload storage adapter 复用' },

<Callout variant="warning">
  开发期用 MinIO 起在 docker-compose，生产使用阿里云 OSS。两者都走 S3 兼容协议，Payload 的 storage adapter 用同一份配置模型；切换后新上传写入 OSS，已有 MinIO 对象需要通过同步工具迁移。
</Callout>
